### Settings Page Structure and Content
The settings page should be role-aware, displaying only the relevant options based on the user’s permissions. Here’s a proposed structure, divided into sections that align with current capabilities and future-proofed for your backlog:

#### 1. General Settings (All Users)
These settings are available to all authenticated users, regardless of role, and focus on personal account management.

- **Profile Information**:
  - **Fields**: Edit first name, last name, email, phone number, wallet address.
  - **Backend Support**: `UserService.updateUser` in `userService.js` supports updating user details.
  - **Implementation**: A form that sends a PATCH request to `/api/users/:userID` (from `userRoutes.js`).
  - **Purpose**: Allows users to keep their personal information up to date.

- **Password Management**:
  - **Fields**: Current password, new password, confirm new password.
  - **Backend Support**: `UserService.updateUser` with bcrypt for password hashing.
  - **Implementation**: A secure form that sends a PATCH request to `/api/users/:userID` with the new password.
  - **Purpose**: Enables users to change their password securely.
  - **Backlog Alignment**: Supports “Password Reset” by extending this to include a “Forgot Password” link that triggers an email with a reset token (not yet implemented but can reuse SMTP setup).

- **Two-Factor Authentication (2FA)**:
  - **Options**: Enable/disable 2FA, view QR code for authenticator app setup, regenerate recovery codes.
  - **Backend Support**: `AuthController.verify2FA` and `resend2FA` in `authController.js` indicate 2FA is implemented with OTP codes.
  - **Implementation**: A toggle to enable/disable 2FA, a modal to display the QR code (generated via an endpoint like `/api/auth/2fa/setup`), and a button to download recovery codes.
  - **Purpose**: Enhances account security as per the “Two-Factor Authentication (2FA)” backlog item.
  - **Note**: If 2FA setup isn’t fully implemented, add an endpoint in `authRoutes.js` to generate and return a QR code using a library like `qrcode`.

- **Notification Preferences**:
  - **Options**: Choose notification channels (SMS, email, in-app push notifications), set notification frequency (immediate, daily digest), and select event types (e.g., visit updates, timesheet validations).
  - **Backend Support**: `sendSMS` (sms.js) and `transporter` (smtp.js) support SMS and email notifications. Push notifications would require extending the Socket.IO setup in `socket.js`.
  - **Implementation**: A form with checkboxes for channel selection (SMS, email, push) and event types. Store preferences in a new `NotificationPreference` model (to be added) and update via `/api/users/:userID/notifications`.
  - **Purpose**: Aligns with “Notification Preferences” in the backlog, allowing users to customize how they receive updates.
  - **Future-Proofing**: Leave room for push notification integration (e.g., via Firebase) when implementing “Update Notifications Supervisor” and “Update Notifications Manager.”

- **Language Selection**:
  - **Options**: Dropdown to select interface language (e.g., English, French, Arabic).
  - **Backend Support**: Not currently implemented, but can be added by storing a `language` field in the `User` model and updating via `UserService.updateUser`.
  - **Implementation**: A dropdown that sends a PATCH request to `/api/users/:userID` to update the language preference. Use a frontend i18n library (e.g., `i18next`) to handle translations.
  - **Purpose**: Supports “Language Switching” in the backlog.
  - **Note**: Requires frontend translation files and possibly backend middleware to set the response language based on user preference.

#### 2. Supervisor Settings (Supervisors Only)
These settings are specific to users with supervisor permissions, focusing on visit and timesheet management.

### Role-Based Access to Settings
To ensure the settings page respects role-based access control (RBAC), use the backend’s `authenticateJWT` and `requirePermission` middleware (security.js) to restrict sections:

- **General Settings**: Accessible to all authenticated users (`authenticateJWT` only).
- **Supervisor Settings**: Restricted to users with supervisor permissions (e.g., `requirePermission('manage_visits')`).
- **Admin Settings**: Restricted to Administrators and Super Admins (e.g., `requirePermission('manage_system')`).
- **Manager/HR/Purchase/Regional Manager Settings**: Restricted to specific roles (e.g., `requirePermission('view_manager_dashboard')`).

On the frontend, fetch the user’s roles and permissions via `/api/users/:userID/roles` and `/api/permissions/effective/:userID` to conditionally render settings sections.

### Sample Settings Page Mockup (React)
Here’s a high-level example of how the settings page could be structured in React:

```jsx
import React, { useEffect, useState } from 'react';
import axios from 'axios';
import { Tabs, Form, Input, Switch, Select } from 'antd';

const SettingsPage = () => {
  const [user, setUser] = useState(null);
  const [permissions, setPermissions] = useState([]);

  useEffect(() => {
    // Fetch user and permissions
    axios.get('/api/users/me', { headers: { Authorization: `Bearer ${localStorage.getItem('token')}` } })
      .then(res => setUser(res.data));
    axios.get('/api/permissions/effective/me', { headers: { Authorization: `Bearer ${localStorage.getItem('token')}` } })
      .then(res => setPermissions(res.data));
  }, []);

  const canAccessAdmin = permissions.includes('manage_system');
  const canAccessSupervisor = permissions.includes('manage_visits');

  return (
    <Tabs>
      <Tabs.TabPane tab="General" key="general">
        <Form layout="vertical">
          <Form.Item label="Full Name">
            <Input value={user?.firstname + ' ' + user?.lastname} />
          </Form.Item>
          <Form.Item label="Email">
            <Input value={user?.email} />
          </Form.Item>
          <Form.Item label="2FA">
            <Switch checked={user?.is2FAEnabled} />
          </Form.Item>
          <Form.Item label="Notifications">
            <Select mode="multiple" options={[
              { value: 'sms', label: 'SMS' },
              { value: 'email', label: 'Email' },
              { value: 'push', label: 'Push' },
            ]} />
          </Form.Item>
          <Form.Item label="Language">
            <Select options={[
              { value: 'en', label: 'English' },
              { value: 'fr', label: 'French' },
              { value: 'ar', label: 'Arabic' },
            ]} />
          </Form.Item>
        </Form>
      </Tabs.TabPane>
      {canAccessSupervisor && (
        <Tabs.TabPane tab="Supervisor" key="supervisor">
          <Form layout="vertical">
            <Form.Item label="Offline Mode">
              <Switch />
            </Form.Item>
            <Form.Item label="Google Calendar">
              <button>Connect to Google</button>
            </Form.Item>
            <Form.Item label="Proximity Notifications">
              <Switch />
            </Form.Item>
          </Form>
        </Tabs.TabPane>
      )}
      {canAccessAdmin && (
        <Tabs.TabPane tab="Admin" key="admin">
          <Form layout="vertical">
            <Form.Item label="Google Maps API Key">
              <Input />
            </Form.Item>
            <Form.Item label="AI Anomaly Threshold">
              <Input type="number" />
            </Form.Item>
          </Form>
        </Tabs.TabPane>
      )}
    </Tabs>
  );
};

export default SettingsPage;
```
