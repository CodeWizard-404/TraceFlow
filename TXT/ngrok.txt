The issue you're facing is a common challenge when integrating Google OAuth with Keycloak in a development environment, especially for mobile apps. The core problem is that Google Cloud Console does not allow IP addresses (e.g., `http://192.168.1.23:8080`) as authorized redirect URIs, requiring a domain name like `localhost` or a fully qualified domain name (FQDN). However, when you set Keycloak to use `localhost`, your Android device cannot access it because `localhost` resolves to the device itself, not your development machine. This creates a conflict between Google’s restrictions and mobile app accessibility.

Here’s a step-by-step solution to resolve this, allowing your Flutter app’s Google login to work with Keycloak and match the web platform’s behavior, while addressing the redirect URI issue and ensuring accessibility from your Android device.

---

### Why the Problem Occurs

1. **Google Cloud Console Restrictions**:
   - Google’s OAuth 2.0 policies require redirect URIs to use `https` (or `http` for `localhost`) and a valid domain name. IP addresses like `192.168.1.23` are not allowed.
   - Your Keycloak identity provider uses `http://192.168.1.23:8080/realms/TraceFlow/broker/google/endpoint`, which is invalid for Google’s OAuth client.

2. **Localhost Inaccessibility**:
   - When Keycloak is configured with `localhost` (e.g., `http://localhost:8080`), it’s only accessible from the machine running Keycloak (your development PC). Your Android device, being a separate device on the same network, cannot resolve `localhost` to your PC’s IP address.

3. **Mobile App Redirect Handling**:
   - The Flutter app uses `flutter_web_auth` with a redirect URI (e.g., `http://192.168.1.23:8080/...` or `myapp://callback`). If the redirect URI doesn’t match Google’s authorized URIs or Keycloak’s settings, the OAuth flow fails.

---

### Solution: Use a Local Domain or Custom Scheme

To resolve this, we’ll use a combination of a local domain (via `ngrok` or a hosts file) for Keycloak and a custom scheme (`myapp://callback`) for the mobile app’s redirect URI. This approach satisfies Google’s requirements, allows your Android device to access Keycloak, and ensures the Flutter app’s Google login works like the web platform.

#### Option 1: Use `ngrok` for a Public Domain
`ngrok` creates a public URL (e.g., `https://your-subdomain.ngrok.io`) that tunnels to your local Keycloak server, making it accessible from your Android device and compatible with Google’s redirect URI requirements.

1. **Install and Run `ngrok`**:

     ```bash
     ngrok http 8080
     ```

2. **Update Keycloak Configuration**:
   - In Keycloak Admin Console > Realm: TraceFlow > Identity Providers > Google, update:
     - **Redirect URI**: `https://your-subdomain.ngrok.io/realms/TraceFlow/broker/google/endpoint`
   - Update Keycloak’s frontend URL:
     - Go to Realm Settings > General > Frontend URL.
     - Set to `https://your-subdomain.ngrok.io`.

3. **Update Google Cloud Console**:
   - Go to Google Cloud Console > APIs & Services > Credentials.
   - Edit your OAuth 2.0 Client ID (`1014557993742-bqulvtvi45uur06a1bsj5h9f23dpo992.apps.googleusercontent.com`).

#### Option 2: Use a Custom Scheme for Mobile (`myapp://callback`)
Instead of relying on an HTTP/HTTPS redirect URI, use a custom scheme for the mobile app, which Google supports for mobile apps. This requires configuring your Android app to handle the custom scheme and updating Keycloak accordingly.

##### Steps:
1. **Update Keycloak Identity Provider**:
   - In Keycloak Admin Console > Realm: TraceFlow > Identity Providers > Google, add:
     - **Valid Redirect URIs**: `myapp://callback`
   - Keep the existing `http://192.168.1.23:8080/realms/TraceFlow/broker/google/endpoint` for the web app.

2. **Update Google Cloud Console**:
   - Go to Google Cloud Console > APIs & Services > Credentials.
   - Edit your OAuth 2.0 Client ID.
   - Add the redirect URI: `myapp://callback`.
   - For Android, ensure the package name (e.g., `com.example.traceflow`) and SHA-1 fingerprint are configured.
   - Save the changes.

3. **Update Flutter `constants.dart`**:
   ```dart
   const String baseUrl = 'http://192.168.1.34:5000/api';
   const String keycloakUrl = 'http://192.168.1.23:8080'; // Use IP for Android access
   const String realm = 'TraceFlow';
   const String clientId = 'traceflow-backend';
   const String clientSecret = '9FQJDVvEU3MZvB9CGxuM50IcTVOapED7';
   const String redirectUri = 'myapp://callback';
   ```

4. **Update `auth_service.dart`**:
   ```dart
   static Future<Map<String, dynamic>> initiateKeycloakLogin() async {
     try {
       final authUrl =
           '$keycloakUrl/realms/$realm/protocol/openid-connect/auth?client_id=$clientId&redirect_uri=${Uri.encodeComponent(redirectUri)}&response_type=code&scope=openid%20email%20profile&kc_idp_hint=google&prompt=select_account';
       final result = await FlutterWebAuth.authenticate(
         url: authUrl,
         callbackUrlScheme: 'myapp', // Matches custom scheme
         preferEphemeral: true,
       );
       final code = Uri.parse(result).queryParameters['code'];
       if (code == null) throw Exception('No authorization code received');

       // Exchange code for tokens
       final tokenResponse = await http.post(
         Uri.parse('$keycloakUrl/realms/$realm/protocol/openid-connect/token'),
         headers: {'Content-Type': 'application/x-www-form-urlencoded'},
         body: {
           'grant_type': 'authorization_code',
           'code': code,
           'redirect_uri': redirectUri,
           'client_id': clientId,
           'client_secret': clientSecret,
         },
       );
       if (tokenResponse.statusCode != 200) {
         throw Exception('Failed to exchange code: ${json.decode(tokenResponse.body)['error_description'] ?? tokenResponse.body}');
       }

       // Rest of the method remains unchanged
     } catch (e) {
       throw Exception(_parseError(e.toString()));
     }
   }
   ```

5. **Configure Android (`android/app/src/main/AndroidManifest.xml`)**:
   ```xml
   <manifest ...>
       <application ...>
           <activity android:name="com.linusu.flutter_web_auth.CallbackActivity">
               <intent-filter android:label="flutter_web_auth">
                   <action android:name="android.intent.action.VIEW" />
                   <category android:name="android.intent.category.DEFAULT" />
                   <category android:name="android.intent.category.BROWSABLE" />
                   <data android:scheme="myapp" />
               </intent-filter>
           </activity>
       </application>
   </manifest>
   ```

6. **Configure iOS (`ios/Runner/Info.plist`)**:
   ```xml
   <key>CFBundleURLTypes</key>
   <array>
       <dict>
           <key>CFBundleTypeRole</key>
           <string>Editor</string>
           <key>CFBundleURLSchemes</key>
           <array>
               <string>myapp</string>
           </array>
       </dict>
   </array>
   ```

7. **Ensure Keycloak is Accessible**:
   - Run Keycloak on `http://192.168.1.23:8080`.
   - Verify your Android device can access it by opening `http://192.168.1.23:8080` in a browser on the device. If it fails, check your firewall or network settings (ensure port 8080 is open and devices are on the same Wi-Fi network).

8. **Test the App**:
   - Run the Flutter app on your Android device: `flutter run`.
   - Tap the “Sign in with Google” button. It should redirect to Google’s login page and return to the app via `myapp://callback`.

**Pros**:
- No external tools like `ngrok` required.
- Custom scheme is mobile-specific and aligns with Google’s OAuth for apps.
- Works with your existing IP-based Keycloak setup.

**Cons**:
- Requires separate redirect URIs for web and mobile.
- Android/iOS configuration adds setup steps.

#### Option 3: Use a Local Domain via Hosts File
If you prefer not to use `ngrok` or a custom scheme, you can map a domain (e.g., `keycloak.local`) to `192.168.1.23` on your network.

##### Steps:
1. **Set Up a Local Domain**:
   - On your development PC, edit the hosts file:
     - **Windows**: `C:\Windows\System32\drivers\etc\hosts`
     - **Mac/Linux**: `/etc/hosts`
     - Add:
       ```
       192.168.1.23 keycloak.local
       ```
   - On your Android device, you may need to modify the hosts file (requires root) or use a DNS override (e.g., via a custom DNS app or router settings) to map `keycloak.local` to `192.168.1.23`.

2. **Update Keycloak**:
   - Set Frontend URL to `http://keycloak.local:8080`.
   - Update Identity Provider > Google > Redirect URI to `http://keycloak.local:8080/realms/TraceFlow/broker/google/endpoint`.

3. **Update Google Cloud Console**:
   - Add `http://keycloak.local:8080/realms/TraceFlow/broker/google/endpoint` as an authorized redirect URI.
   - Note: Google may reject non-standard domains like `.local` unless you own a custom domain.

4. **Update Flutter `constants.dart`**:
   ```dart
   const String baseUrl = 'http://192.168.1.34:5000/api';
   const String keycloakUrl = 'http://keycloak.local:8080';
   const String realm = 'TraceFlow';
   const String clientId = 'traceflow-backend';
   const String clientSecret = '9FQJDVvEU3MZvB9CGxuM50IcTVOapED7';
   const String redirectUri = 'http://keycloak.local:8080/realms/TraceFlow/broker/google/endpoint';
   ```

5. **Test the App**:
   - Ensure Keycloak is running and accessible at `http://keycloak.local:8080` from your Android device.
   - Run the Flutter app and test the Google login.

**Pros**:
- Mimics production-like domain setup.
- No external services required.

**Cons**:
- Modifying hosts on Android is complex (root required).
- Google may reject `.local` domains.
- Network configuration can be error-prone.

### Additional Fixes for Android Access
If your Android device still can’t access Keycloak at `http://192.168.1.23:8080`:
1. **Check Network**:
   - Ensure both your PC and Android device are on the same Wi-Fi network.
   - Verify your PC’s IP (`192.168.1.23`) hasn’t changed (use `ipconfig` on Windows or `ifconfig` on Mac/Linux).

2. **Firewall Settings**:
   - On your PC, allow incoming connections on port 8080:
     - **Windows**: Add a rule in Windows Defender Firewall.
     - **Mac**: Allow in System Preferences > Security & Privacy > Firewall.
     - **Linux**: Use `ufw allow 8080`.

3. **Test Connectivity**:
   - From your Android device’s browser, visit `http://192.168.1.23:8080`. You should see the Keycloak welcome page.
   - If it fails, try pinging `192.168.1.23` from your Android device (use a terminal app or adb shell).

4. **Keycloak Binding**:
   - Ensure Keycloak binds to `0.0.0.0` (all interfaces), not just `localhost`. Start Keycloak with:
     ```bash
     ./standalone.sh -b 0.0.0.0
     ```
   - Or edit `standalone.xml` in Keycloak’s `configuration` directory to set `<interfaces><interface name="public"><any-address/></interface></interfaces>`.
